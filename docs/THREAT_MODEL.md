# TRUST404 구현 위협 모델

## 자산과 역할

- **에이전트 키:** 결제 요청의 금액, 통화, 목적지, 요청 ID, 기업 키를 서명합니다.
- **기업 키:** 적용할 정책 버전과 한도를 서명합니다.
- **운영자 키:** 요청 접수, 정책 결정, 순서 있는 로그 항목, 체크포인트를 서명합니다.
- **witness 키:** 운영자 체크포인트를 별도 DB의 이전 체크포인트와 대조하고 영수증을 서명합니다.
- **감사자가 보관한 증거:** 운영자·에이전트·기업·witness 공개키, 접수 영수증, 체크포인트 지문 또는 witness 영수증입니다.

독립 검증기는 운영자 SQLite DB를 읽지 않습니다. 전체 로그를 담은 증명 파일과 위 증거로 서명, 해시 연결, 정책 결과, 접수 이후 결정의 존재를 검사합니다.

## 주요 공격자

분쟁 이후의 **운영자**가 자신의 SQLite DB와 운영자 서명키를 통제한다고 가정합니다. 운영자는 로그를 편집·삭제하고 새 로그에 다시 서명할 수 있습니다. 에이전트 키, 기업 키, 별도 운영되는 witness 키와 감사자가 이미 받은 증거는 통제하지 못한다고 가정합니다.

파일만 바꿀 수 있고 서명키는 없는 공격자도 포함합니다. 이 경우 항목 해시와 서명이 직접 실패합니다. 운영자가 자기 키로 다시 서명하는 공격은 더 강하며, 이전에 외부로 전달한 접수 영수증이나 체크포인트가 있어야 과거의 재작성을 드러낼 수 있습니다.

## 탐지 조건

| 행위 | 필요한 독립 증거 | 검증 결과 |
| --- | --- | --- |
| 거절 사유·금액·정책 한도를 파일에서 수정 | 신뢰하는 운영자·기업·에이전트 공개키 | 항목 해시·서명, 정책 서명 또는 재계산 실패 |
| 운영자가 결정 항목을 삭제하고 새 로그에 서명 | 원래 체크포인트 지문 또는 witness 영수증 | 이전 체크포인트와 불일치 |
| 운영자가 접수와 결정을 함께 지우고 빈 로그에 다시 서명 | 감사자가 보관한 접수 영수증 또는 이전 witness 영수증 | `ACCEPTANCE_OMITTED` 또는 witness 영수증 불일치 |
| 접수 항목이 있으나 해당 스냅샷에 결정이 없음 | 서명된 접수가 포함된 증명 | `MISSING_DECISION` |
| witness에 이미 증명된 로그의 분기·롤백을 제출 | witness의 이전 상태와 별도 서명키 | witness가 서명을 거부 |

재서명된 빈 로그는 그 로그와 함께 새로 제시된 지문만 검증하면 **유효**합니다. 이는 암호학적 검증 실패가 아니라 신뢰할 수 있는 외부 기준점이 없을 때의 한계입니다. `scripts/attack_report.py`는 이 경계를 일부러 보여줍니다.

## 신뢰 가정

1. 감사자는 공개키를 결제 운영자와 다른 경로로 확인합니다. 증명 안에 적힌 공개키만 믿으면 실세계 소유자를 검증할 수 없습니다. CLI의 `--agent-key`, `--enterprise-key`, `--issuer-key`, `--witness-key`가 외부 신뢰 값을 전달합니다.
2. 감사자는 접수 영수증을 접수 시점에 보관하거나, 체크포인트 지문 또는 witness 영수증을 운영자가 바꾸지 못하는 곳에 보관합니다.
3. witness는 운영자와 다른 관리 주체가 키·DB를 통제합니다. Compose 데모의 두 컨테이너는 프로세스 분리만 보여주며, 같은 호스트와 관리 계정을 쓰므로 조직적 독립성을 증명하지 않습니다.
4. Ed25519 서명키가 안전하고 SHA-256 충돌 저항성이 유지됩니다. witness의 `issued_at`은 witness 시계에 대한 주장입니다.

## 보장하지 않는 것

- 접수 영수증을 발행하지 않은 요청을 운영자가 실제로 받았다는 사실.
- `MISSING_DECISION`이 처리 기한 위반인지 여부. 현재 구현은 체크포인트 시점의 부재만 보고합니다.
- 기업이 서명한 정책이 그 시점에 최신·유효했는지 여부. 정책 폐기, 시행 시각, 조직 키 등록은 범위 밖입니다.
- 결제 실행과 정산의 정확성, 실자금 보호, KYC·KYT, 결제 수신자 신원.
- 같은 서명 요청을 다른 운영자 로그에 제출하는 전역 재생 방지. 요청 ID 중복은 해당 로그 안에서만 막습니다.
- witness 자체의 악의적 이중 서명이나 이력 끝부분 은폐를 공개 네트워크 전체에서 탐지하는 것. `witness-history --expected-latest-hash`는 별도로 보관한 최신 영수증 해시와 대조합니다.
- 공개 블록체인 테스트넷 앵커, TLS 종료, 프로덕션 비밀 관리, 개인정보 보호용 선택적 공개. 전체 증명에는 금액과 목적지가 들어 있습니다.
